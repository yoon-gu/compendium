에이전트가 일하는 도중에 파일이 바뀌면 모델은 어떻게 알까요? 사람이 아무것도 치지 않았는데 에이전트가 다시 말을 거는 건 어떤 원리일까요?
파이썬으로 만든 코딩 에이전트에 알림 큐 하나와 백그라운드 작업을 붙여, 모델이 바뀐 세상을 알아채고 느린 테스트를 기다리지 않게 만드는 핸즈온 강의 3편입니다.

WSO2에서 코딩 도우미를 세 개 만든 Isuru Wijesiri의 공개 책 "Harness Engineering 101"을 교재로 삼았습니다. 책의 장난감 하니스(MIT 라이선스)를 Anthropic API의 Claude Haiku로 실제로 돌렸고, 화면의 터미널은 그 실행 기록을 글자 그대로 다시 그린 것입니다. 터미널 아래에서는 지금 그 출력을 만든 코드 줄이 함께 켜집니다.

이 영상에서 하는 것
- 수업 9 리마인더: 모델은 배열에 있는 것만 압니다. 모델이 파일을 읽은 직후 사람이 함수를 하나 추가하면, 알림이 없는 판은 옛 내용으로 파일을 덮어써 그 함수를 지워 버립니다. 알림을 켜면 모델이 다시 읽고 세 함수 모두에 타입 힌트를 답니다.
- 왜 맨 아래에 붙이나: 앞을 고치면 프롬프트 캐시가 깨지고, 모델은 최근 글을 더 잘 봅니다. 배열 끝을 열어 실제로 무엇이 붙는지도 봅니다.
- 할 일 목록: 모델이 스스로 거는 알림입니다. 목록을 바퀴마다 맨 아래에 다시 붙여 계획이 흐려지지 않게 합니다. 너무 자주 알리면 모델이 흘려듣는다는 점도 짚습니다.
- 수업 10 백그라운드 작업: 30초 걸리는 테스트를 뒤로 돌리고 그동안 README 오타를 고칩니다. 9초에 모델이 말을 마친 뒤 아무도 입력하지 않았는데, 36초에 테스트가 끝나자 하니스가 모델을 깨웁니다.
- 누가 모델을 불렀나: 입력 대기를 0.3초씩 잘게 나눠 틈마다 큐를 보는 코드 몇 줄로, 모델이 저절로 도는 것처럼 보이는 장면의 속을 풉니다.

이런 분께 맞습니다
- Claude Code의 system-reminder나 할 일 목록이 왜 있는지 궁금한 개발자
- 에이전트에게 오래 걸리는 빌드·테스트를 맡기면 멈추거나 sleep으로 버티는 문제를 겪은 분
- 사람 입력 없이 이벤트로 깨어나는 에이전트를 직접 만들어 보고 싶은 분
- 1·2편을 보셨거나, 파이썬과 LLM API를 한 번이라도 다뤄 본 분
