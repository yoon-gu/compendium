# 하니스 엔지니어링 101 핸즈온 강의 — 목차 (2026-10-20 확정)

원문: Isuru Wijesiri, *Harness Engineering 101* (본문 CC BY-NC-ND 4.0, 코드 MIT) — https://github.com/IsuruMaduranga/harness-engineering-101
노트: https://yoon-gu.github.io/compendium/notes/harness-engineering-101/

## 형식

- 가로 1920x1080 (`build.py --wide`): 왼쪽 글, 오른쪽 코드·터미널 녹화·모션 그래픽
- 친절한 핸즈온 강사가 시청자에게 존댓말로 이끈다. 나레이션 1인(진우)
- 세 편, 편마다 12-15분, 유튜브 재생목록 하나로 묶음
- 실습은 `lab/`에서 원문 장난감 하니스(MIT, 출처 표기)를 실제로 돌려 녹화한다
- 대본은 우리 말로 새로 쓴다(본문 변경 금지 라이선스). 화면의 코드는 원문 하니스
- 모델 ID는 실제 호출 가능한 것으로 바꾸고, 대부분의 실험은 Haiku로 돌린다

## 수업 한 개의 틀

1. 코드 같이 쓰기 — 명령·코드를 크게, 바뀐 줄 강조(타이핑 클립, 설명 중인 줄에 네모)
2. 실행해 보기 — 실제 터미널 녹화(나레이션에 동기화)
3. 방금 일어난 일 — 모션 그래픽으로 배열·루프 흐름
4. 자주 막히는 곳 — 실제로 나온 오류 한두 개와 해결
5. 체크포인트 — 한 줄 정리와 "여기까지 확인"

## 1편: 에이전트의 뼈대 (원문 1-5장)

| # | 수업 | 같이 쓰는 것 | 체크포인트 |
|---|---|---|---|
| 0 | 준비물 | Python 3.10+, 저장소 받기, API 키, 모델 ID 한 줄 | `v1_chat.py`가 인사에 답하면 통과 |
| 1 | 30줄 채팅 만들기 (v1) | 코드 한 줄씩, 턴마다 배열 크기 출력 | 서버는 기억하지 않고 기억은 내 리스트에 있다 |
| 2 | 세션 파일 열어 보기 | 저장된 JSON에서 모델의 지난 답을 고치고 이어서 묻기 | 모델은 배열에 적힌 것을 믿는다 |
| 3 | 도구 붙이기 (v2) | `read_file`·`run_command`와 디스패치 표, 두 단계 질문에서 멈추기 | 모델은 부탁하고 실행은 내 코드가 한다 |
| 4 | 루프 하나로 에이전트 (v3) | while 루프, 버그 심은 예제 프로젝트에 "테스트 고쳐 줘" | 에이전트는 while 루프다 |
| 5 | 오류를 돌려주기 | 오류를 뭉갠 판과 그대로 돌려준 판을 나란히 | 오류는 모델의 연료다 |
| 6 | 비용 재기 (캐싱) | 바퀴마다 `cache_read` 출력, 시스템 프롬프트에 현재 시각 넣어 깨 보기 | 위를 고치면 아래 전부를 다시 낸다 |
