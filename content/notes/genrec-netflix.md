## 한눈에 보기

넷플릭스의 기존 추천 랭커는 수천 개의 손설계 피처와 여러 해 다듬은 전용 아키텍처로 돌아간다. 새 콘텐츠 유형(게임, 라이브, 팟캐스트)이나 새 화면을 붙일 때마다 피처, 모델, 인프라를 다시 손봐야 해서 사업 속도를 따라가기 어려워졌다. GenRec은 이 랭커를 LLM 기반으로 바꾸려는 첫걸음이다.

| 항목 | 기존 프로덕션 랭커 | GenRec |
|---|---|---|
| 입력 | 수천 개의 손설계 피처와 고차 피처 상호작용 | 사용자 이력·맥락·작품 메타데이터를 문장으로 풀어 쓴 텍스트(verbalization) |
| 모델 | 과제별 전용 아키텍처(피처 상호작용망, 시퀀스 트랜스포머, 멀티태스크) | 사내 기반 LLM과 같은 디코더 전용 트랜스포머 + 카탈로그 인식 랭킹 헤드 |
| 학습 | 과제별로 처음부터 | Phase 1(넷플릭스 데이터로 적응한 기반 LLM) 위에 Phase 2 사후 학습 |
| 서빙 | 기존 추천 인프라 | vLLM, 프리필 전용(prefill-only) 단일 순전파로 전체 카탈로그 점수화 |
| 결과 | 기준선 | Phase-2 라벨 약 40배 적게 쓰고 오프라인 MRR +1.6%, 온라인 단기·장기 지표 유의미한 개선 |

## 1. 들어가며 — 왜 LLM 랭커인가

LLM은 넓은 세계 지식과 언어 이해 덕에 사용자, 콘텐츠, 맥락을 기존 구조보다 풍부하게 모델링할 수 있다. 사용자 이력을 자연어로 표현하면 작품의 의미와 취향을 더 깊이 다룰 수 있고, 새 용도는 전용 모델을 다시 설계하는 대신 프롬프트로 추천을 조정(steering)해서 대응할 수 있다.

하지만 기성 LLM을 그대로 추천기로 쓰면 문제가 많다. 전 세계적으로 인기 있는 작품을 과하게 추천하고, 카탈로그에 없는 작품을 지어내고(환각), 사업상의 세밀한 제약을 무시하고, 개인화가 약하다. GenRec은 이걸 네 가지로 푼다.

- 넷플릭스 카탈로그와 회원 행동 데이터로 사후 학습해 넷플릭스 고유의 취향을 배우고 인기작 쏠림을 줄인다.
- 여러 보상 신호를 학습에 넣어 장기 회원 만족과 사업 목표에 맞춘다.
- 출력을 카탈로그 안의 작품으로 제한해 없는 작품 추천을 원천 차단한다.
- 비용 제약 아래 최적화해 넷플릭스 LLM 서빙 스택에 붙인다.

저자들이 강조하는 패러다임 전환은 **피처 엔지니어링에서 컨텍스트 엔지니어링(context engineering)으로**다. 피처 상호작용을 사람이 설계하는 대신, 모델에 어떤 정보를 어떤 표현으로 제한된 토큰 안에 보여 줄지, 어떤 목표와 보상을 최적화할지를 설계한다.

> 해설 — 이 논문에서 가장 실무적인 주장은 데이터 효율이다. Phase 1(기반 모델 학습)은 드물게, Phase 2(랭커 사후 학습)는 자주 다시 돌린다. 자주 돌리는 쪽이 적은 데이터로 충분하다면 랭커를 최신으로 유지하는 비용이 크게 준다. 기반 모델이 이미 사용자와 콘텐츠를 이해하고 있으니 랭커가 그걸 처음부터 다시 배울 필요가 없다는 것이다.

## 2. 관련 연구

두 갈래가 있다. 하나는 특수 토큰을 쓰는 생성형 추천이다. SASRec, BERT4Rec 같은 순차 추천에서 출발해 작품 ID·메타데이터·시간·기기를 특수 토큰으로 어휘에 넣은 산업용 시스템(HSTU, 넷플릭스 기반 모델, PinRec)으로 커졌다. 작품을 의미 코드로 토큰화하는 시맨틱 ID(semantic ID) 계열(TIGER, Google의 랭킹, Kuaishou의 OneRec)도 있다. 이들은 성능은 좋지만 LLM의 세계 지식이나 프롬프트 조정 능력을 물려받기 어렵다.

다른 하나는 사전학습 LLM을 백본으로 쓰는 추천이다. P5, TALLRec, LlamaRec 같은 학계 시스템이 텍스트-투-텍스트로 추천을 풀었고, 산업에서는 Google PLUM(YouTube), Spotify GLIDE, Kuaishou OneRec-Think가 시맨틱 ID 토큰을 LLM 어휘에 넣어 작품을 직접 생성하게 했다.

GenRec이 갈라지는 지점은 추론 방식이다. 생성형 검색 시스템 대부분은 빔 서치(beam search) 같은 자기회귀 디코딩을 쓰는데, 후보가 많으면 지연이 감당하기 어렵다. GenRec은 LLM에 카탈로그 인식 랭킹 헤드를 붙여 후보 전체를 순전파 한 번에 점수화한다.

## 3. 문제 설정

전체 카탈로그 랭킹(후보 집합이 주어지면 상위 K 랭킹)을 푼다. 이렇게 만든 순위 목록은 여러 화면의 작품 순위에도, 하위 애플리케이션의 개인화 입력에도 재사용된다.

요청 하나는 사용자 $u$, 맥락 $\tau$(기기, 화면, 지역, 시간대), 시점 $t$, 그 이전의 상호작용 이력 $H$로 정해진다. 작품 $i$마다 메타데이터 $M_i$(제목, 장르, 줄거리, 공개일)가 있다. 목표는 카탈로그의 순위 $\pi$를 고르되, 단기 참여가 아니라 **장기 회원 효용**(만족과 유지의 대리 지표)의 기댓값을 최대화하는 것이다.

## 4. 방법

### 두 단계 학습 틀

Phase 1은 오픈소스 LLM을 넷플릭스 데이터로 학습해 사용자와 콘텐츠를 깊이 이해하는 기반 LLM을 만든다. Phase 2는 이 기반 모델을 랭킹용 데이터와 목표로 사후 학습(post-training)해 GenRec을 만든다. 두 단계는 목표가 다르다.

| | Phase 1 | Phase 2 |
|---|---|---|
| 역량 초점 | 세계 지식, 개인화, 콘텐츠 이해, 언어 능력의 균형 | 랭킹 품질과 추천 조정 |
| 갱신 주기 | 드물게(장기적 이해) | 자주(신작, 인기 변화, 최근 관심사 추적) |
| 비용 민감도 | 가장 유능한 모델이 목표, 서빙 비용 제약 적음 | 대규모 트래픽을 감당하도록 비용 효율 필수 |

### 사후 학습 데이터 — 시청 기록을 대화로

넷플릭스 회원은 수천억 건의 상호작용 이벤트(재생, 시청 시간, 좋아요, 찜하기 등)를 만든다. GenRec은 회원의 이력을 사용자와 추천기 사이의 단일 턴 또는 멀티 턴 "대화"로 바꾼다.

- 사용자 메시지: 맥락(화면, 시간, 기기, 지역), 프로필과 이력(국가, 가입 기간, 요금제, 과거 상호작용), 작품 정보(ID, 제목, 공개 시점, 줄거리, 인기 추세), 과제(예: 다음에 재생하거나 좋아요를 누를 작품 예측)
- 어시스턴트 메시지: 그 턴에서 회원이 실제로 보인 반응(재생, 시청 시간, 이탈, 좋아요) — 학습의 정답 신호

### 입력 문장화와 컨텍스트 엔지니어링

회원의 이력은 이벤트 수도 많고 이벤트마다 메타데이터도 풍부해서 토큰 예산을 쉽게 넘는다. 컨텍스트가 길면 어텐션이 희석되고 학습·추론 비용도 커진다. 그래서 무엇을 넣을지 고른다.

- 신호가 강한 참여(오래 본 재생, 좋아요)는 풍부한 메타데이터와 함께 그대로 넣는다.
- 신호가 약한 최근 이벤트(아주 짧은 재생, 잡음 섞인 조회·클릭)는 아예 뺀다.
- 몰아보기처럼 반복되는 행동은 이벤트마다 나열하지 않고 압축한다.
- 신작이나 콜드 스타트(cold-start) 작품처럼 중요한데 정보가 부족한 작품은 메타데이터를 더 자세히 넣는다.

단기·중기 이력은 촘촘하게, 오래된 이력은 빼거나 짧은 관심사 요약으로 줄인다.

### 학습 목표

두 목표를 섞는다.

- 추천 랭킹 목표: 가치 있는 참여(오래 본 재생, 강한 명시적 피드백)를 양성 라벨로 삼아, 카탈로그(또는 후보 집합) 전체에 대한 교차 엔트로피(cross entropy)로 학습한다. 잡음 제거 기준과 임계값은 콘텐츠 유형마다 다르다.
- 언어 모델링 목표: 문장화된 입력과 출력의 토큰을 예측하게 해 백본의 언어 이해를 유지한다. 풍부한 자연어 이력을 다루는 데, 그리고 프롬프트로 추천을 조정하는 데 필요하다.

전체 손실은 이들의 가중합이다.

$$\mathcal{L} = \alpha \cdot \mathcal{L}_{\text{ranking}} + \beta \cdot \mathcal{L}_{\text{language}} + \gamma \cdot \mathcal{L}_{\text{misc}}, \quad \alpha + \beta + \gamma = 1$$

추론 때는 랭킹 과제만 쓴다. 언어 모델링은 랭킹에 보완 정보를 주고, 프롬프트 조정 능력을 지키고, 나중에 자연어 설명 같은 생성 용도를 열어 두는 역할이다.

### 모델 구조 — 카탈로그 인식 랭킹 헤드

백본은 기반 LLM과 같은 디코더 전용 트랜스포머다. 점수는 세 단계로 낸다.

1. 문장화: 문장화기 $V$가 이력, 맥락, 작품 메타데이터를 하나의 텍스트 $x$로 만든다.
2. 풀링 표현: LLM이 $x$를 읽고, 정해진 풀링 위치의 은닉 상태를 $d$차원 표현 $h$로 꺼낸다. 사용자 취향과 맥락의 요약이다.
3. 카탈로그 인식 점수: 점수 헤드 $\phi$가 $h$와 작품마다 학습된 $d$차원 임베딩 $e_i$를 결합해 점수를 낸다.

LLM 가중치, 점수 헤드, 작품 임베딩은 함께 학습한다. 카탈로그에 대한 소프트맥스로 확률 분포를 만들고 점수 순으로 순위를 얻는다. 카탈로그가 너무 크면 샘플링 소프트맥스(sampled softmax)를 쓴다. 출력 공간이 카탈로그 임베딩이므로 없는 작품을 추천할 수가 없다.

### 보상 신호 — 보상 가중 랭킹 손실

원시 상호작용만으로 학습하면 몰아보기를 탐색보다 과하게 추천하거나, 게임보다 영상을 편애하거나, 당장의 클릭만 키우는 쪽으로 흐를 수 있다. 그래서 별도의 보상 모델에서 나온 두 종류의 보상을 넣는다.

- 장기 만족 대리 지표: 단기 참여가 장기 결과(서비스 재방문, 카탈로그의 더 넓은 탐색, 지속적 참여)와 얼마나 연결되는지 추정한다. 진짜 장기 지표는 잡음이 많고 늦게 나오기 때문에 과거 데이터로 학습한 안정적인 대리 지표를 쓴다.
- 행동 재조정: 콘텐츠 유형(영화, 게임, 라이브, 팟캐스트)과 공개 단계(공개 전, 신작, 스테디셀러) 사이의 균형을 맞춰 유형별 노출 공정성 같은 사업 목표를 지킨다.

여러 보상 모델의 출력을 학습 예시마다 하나의 가중치로 합치고, 그 예시의 랭킹 손실에 곱한다. 가치 높은 참여는 크게, 바람직하지 않은 행동은 작게 반영된다. 예비 실험에서 GRPO 같은 강화학습 방식이 지도 미세조정보다 더 좋았지만 학습 비용이 커서 후속 과제로 미뤘다. 지금은 단순하고 안정적이고 싼 보상 가중 손실을 주된 정렬 수단으로 쓴다.

### 온라인 서빙과 비용

넷플릭스 규모에서 추론 비용은 대략 모델 크기와 컨텍스트 길이의 곱에 비례한다. 그래서 두 축을 함께 줄인다. 하나는 더 크거나 표적화된 데이터로 학습한 작은 모델과 증류(distillation) 모델을 쓰는 것, 다른 하나는 문장화 압축으로 컨텍스트를 줄이는 것이다.

세 번째 지렛대는 추론 방식이다. 후보 전체를 순위 매기는데 토큰을 하나씩 생성하거나 빔 서치를 돌리면 감당할 수 없다. 그래서 백본이 생성형인데도 일부러 **프리필 전용**으로 배포한다. 입력을 한 번 읽고 순전파 한 번으로 후보 전체의 점수를 낸다.

> 해설 — "생성형 LLM을 생성에 쓰지 않는다"는 선택이 이 논문의 실용성을 만든다. LLM은 사용자 이해를 위한 인코더로 쓰고, 출력은 전통적인 임베딩 내적 점수로 받는다. 덕분에 환각 문제와 디코딩 지연 문제가 한 번에 사라진다. 대신 자연어 설명 같은 생성형의 장점은 언어 모델링 목표로 "열어 두기만" 한 상태다.

## 5. 실험과 결과

### GenRec 대 프로덕션 기준선

기준선은 여러 해 다듬은 판별(discriminative) 모델이다.

- 오프라인: Phase-2 라벨 학습 예시를 약 **40배 적게** 쓰고도 평균 역순위(Mean Reciprocal Rank, MRR)에서 상대 약 +1.6%. 데이터와 입력 신호를 늘리면 더 오른다.
- 온라인: 배치 연산 화면을 대상으로 넷플릭스 트래픽 약 10%에서 약 4주간 A/B 테스트. 데이터와 신호를 적게 쓴 설정에서도 단기·장기 온라인 지표 모두 통계적으로 유의미하게 개선됐다. 핵심 온라인 지표는 상대 +0.006%로, 넷플릭스 규모에서는 의미 있는 차이라고 한다.

### 데이터와 모델 스케일링

- 데이터: Phase-2 데이터를 가장 작은 설정의 1배에서 20배까지 늘리며, 약 1B와 약 10B 두 크기의 백본으로 실험했다. 두 크기 모두 MRR이 데이터에 따라 단조 증가했고, 1B는 절대값이 낮지만 증가 양상은 10B와 비슷했다.
- 모델: 같은 GPU 구성과 비슷한 학습 시간을 고정하고 1B-10B 범위에서 비교하면 큰 백본이 일관되게 더 높은 MRR을 냈다.
- 품질-비용: 둘 다 품질을 올리지만 학습·서빙 비용도 올린다. Phase 2는 자주 학습하고 대규모 트래픽을 직접 받으므로, 스케일링 곡선과 컨텍스트 길이 실험을 함께 보고 품질-비용 파레토 경계에서 대부분의 품질 이득을 얻으면서 예산 안에 드는 지점을 고른다.

### Phase 1과 Phase 2의 기여

| | 오프라인 랭킹 지표(MRR) |
|---|---|
| Phase 1의 효과 | 기성 오픈소스 LLM을 백본으로 쓸 때보다 +10-20% |
| Phase 2의 효과 | Phase 1 학습 시점 기준 +35-50%, 2주 뒤에는 약 +80%로 커짐 |

Phase 2의 효과가 시간이 갈수록 커지는 건, 과제 특화 적응 자체의 힘에 더해 드물게 갱신되는 Phase 1 백본이 인기 추세와 관심사 변화에 뒤처지기 때문이다.

### 컨텍스트 길이 최적화

컨텍스트 창은 품질의 동력이자 비용의 동력이다. 세 단계로 압축했다.

1. 이벤트 선택과 압축: 약한 신호를 빼고 반복을 압축하고 강한 신호를 남겨 깨끗한 이벤트 열을 만든다.
2. 이력 길이 탐색: 남길 이벤트 수를 바꿔 가며 MRR을 그리면 팔꿈치 지점(elbow point)이 나온다. 그 뒤로는 토큰을 늘려도 이득이 미미하다.
3. 간결한 문장화: 이벤트마다 세부 정보의 수준, 문구 단순화, 퓨샷 예시 제거 등을 바꿔 가며 성능을 잰다.

결과적으로 컨텍스트를 약 5,000토큰에서 약 1,700토큰, 대략 **3분의 1**로 줄여도 오프라인 지표 손실은 무시할 만했다. GenRec은 연산이 병목이라 서빙 비용도 거의 그대로 3분의 1로 줄었다.

> 해설 — 1.6%라는 오프라인 개선 폭보다 "40배 적은 라벨"과 "3분의 1 컨텍스트"가 더 눈에 띈다. 다만 정확한 데이터 규모, 모델 크기, 온라인 지표의 정의는 공개하지 않아서 다른 조직이 숫자를 그대로 비교하기는 어렵다. 온라인 테스트 대상도 배치 연산 화면이라, 실시간 요청 경로에서의 지연과 비용은 아직 검증되지 않은 영역이다.

## 6. 논의 — LLM 네이티브 추천

저자들은 LLM 기반 추천으로의 이동이 "랭커를 트랜스포머로 갈아 끼우는 일"이 아니라고 말한다. 다섯 가지가 바뀐다.

- 피처 엔지니어링에서 컨텍스트 엔지니어링으로: 프롬프트가 새로운 피처 벡터가 된다. 어떤 신호를 넣을지, 어떻게 요약할지, 얼마나 과거까지 볼지, 한정된 토큰에 어떻게 담을지가 모델링 작업이 된다.
- 맞춤 아키텍처에서 기반 백본으로: 투타워, DLRM식 피처 상호작용망, 전용 어텐션 블록 같은 과제별 설계 대신 기반 모델의 트랜스포머를 표준으로 쓴다. 혁신은 데이터, 스케일링 법칙, 사후 학습 전략, 추론 최적화로 한 층 올라간다.
- 설계 지침으로서의 스케일링 법칙: 희소 ID와 과제별 구조 때문에 일찍 수확 체감에 부딪히던 고전 추천과 달리, 데이터와 모델 크기에 따른 단조 개선을 사후 관찰이 아니라 설계의 기준으로 쓸 수 있다.
- 사전학습, 사후 학습, 보상 정렬: 추천기마다 처음부터 만드는 대신 하나의 기반 모델을 여러 용도가 재사용하고, 각자 가벼운 사후 학습과 보상으로 적응한다.
- 추천 인프라에서 LLM 인프라로: 긴 이력 컨텍스트 때문에 KV 캐시, 프리픽스 캐시, 프리필 전용 추론이 핵심 지렛대가 된다. 서빙 스택은 MLP나 행렬 분해 중심의 고전 추천 인프라보다 GPU, vLLM, Triton 기반의 현대 LLM 인프라를 닮아 간다.

## 7. 결론

GenRec은 사용자 이력과 맥락을 문장화하고, 카탈로그 인식 랭킹 헤드를 붙이고, 여러 보상 신호로 학습해서, 오래 다듬은 프로덕션 랭커보다 훨씬 적은 라벨과 입력 신호로 단기·장기 온라인 지표를 모두 유의미하게 개선했다. 저자들은 이를 넷플릭스 추천 스택이 LLM 중심으로 옮겨 가는 첫걸음으로 보고, 비용과 인프라 복잡도를 관리하고 강한 비LLM 기준선과 엄격하게 비교하는 한 적어도 일부 상황에서는 실현 가능한 길이라고 결론짓는다.

## 읽으며 짚어 둘 점

- 산업 논문답게 결과는 상대 수치와 범위로만 나온다. 모델 크기도 "약 1B", "약 10B" 수준으로만 밝힌다.
- 논문은 Phase 2만 다룬다. GenRec 성능의 상당 부분(+10-20%)은 공개되지 않은 Phase 1 기반 모델에서 온다. 같은 결과를 재현하려면 도메인에 적응한 기반 모델부터 필요하다.
- 온라인 실험은 배치 연산 화면에 한정된다. 실시간 개인화 경로까지 같은 비용 구조가 유지될지는 열린 문제다.
- 강화학습(GRPO)이 더 좋았다는 예비 결과는 있지만, 비용 때문에 보상 가중 손실을 택했다는 점이 실무적으로 솔직하다.

## 남는 생각

이 논문에서 가져갈 것은 모델보다 작업의 이동이다. 추천 팀이 하던 피처 설계가 "무엇을 어떤 문장으로 몇 토큰 안에 보여 줄 것인가"라는 컨텍스트 설계로 바뀐다. 컨텍스트를 3분의 1로 줄여도 품질이 거의 그대로였다는 결과는, 이 새 작업에도 예전 피처 선택만큼의 실험과 판단이 필요하다는 뜻이기도 하다.
